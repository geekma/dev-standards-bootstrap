## 2.5 阶段 2·三维影响详述

> 必含清单条目名与验收标准（唯一权威）在 DS 阶段 2；本节承载条 1/2/3 的完整阐释（条 4/5 延伸发现/历史相似检索全文在 DS，A30 锚点）：

1. **业务影响**：受影响业务流程与用户场景（端到端旅程）、上下游系统与数据流、行业/合规约束（如金融、医疗、数据出境）、SLA 与体验阈值——从行业与业务视角回答"这个变更会改变什么业务行为、波及哪些流程"。
2. **技术影响**：调用拓扑图（入口→链路→出口）、受影响类/文件清单、爆炸半径（Blast Radius）评估（含被波及的"看似无关"调用方与共享组件）；命中状态/触发链路类变更时，补做隐式链路三向遍历（正向调用点 / 反向 watcher·事件·钩子 / 事件源×归宿矩阵），方法见 `resources/methodologies/state-trigger-audit.md`（v3.4.0）。
3. **风险与回滚**：风险矩阵（概率 × 影响表，高风险项附缓解措施）、回滚策略。

## 2.5 阶段 4·覆盖维度与场景枚举细则

- **变更动态约束（v3.10.0）**：从本变更 spec 与**前序产物**合成的不变量——类型参考 SCHEMA/协议/关系型/溯源型/时序型/能力型（arXiv:2602.02475 附录 F）；每条含检查方式与**显式失败路径**；step-by-step 合成优于 one-shot（§4.4 实证）。
- **覆盖维度矩阵（v2.20.0；v3.2.0 扩为十一类）枚举细则**：功能正常流 / **业务场景**（端到端旅程，按 01-spec 用户故事）/ **逻辑分支** / 边界值与空值 / **异常与降级兜底**（依赖故障注入，覆盖 LLM 与非 LLM）/ **数据组合与状态** / **并发与竞态**（引入共享可变状态或并发原语时**必须**，方法见 `resources/methodologies/development.md` §3.6；未引入方可标"不适用"）/ **安全**（越权/注入/敏感数据，如适用）/ **兼容性**（接口前后兼容、多端）/ **性能与容量**（命中 01-spec 非功能指标时**必须**；未命中显式标注）/ **回归**（受影响既有功能）。L0/L1 可裁剪但**逐维显式标注"不适用，理由"**，禁止静默裁剪（§2.16.6 第 3 条）；**风险联动（v3.2.0）**：L3 安全维度强制（命中 PII/认证授权/对外接口不得标"不适用"）、命中性能指标时性能维度强制；复用 vs 新增按门禁 2 判定（打点必须断言内容，合入前跑全量回归）。
- **业务场景全景枚举与覆盖率（v3.3.0，业务专家视角）细则**：从用户故事按**五维**枚举——①角色/权限 ②状态与迁移 ③端到端链路（含跨模块）④时序与并发 ⑤异常业务路径——**隐含场景必须入清单**。落 04「业务场景清单」节（SC-xxx + 描述 + 关联 REQ + 覆盖 TC，追加式，每条 SC 至少映射一个 TC）；**覆盖率 = 已覆盖/枚举 ≥80%**（L3 ≥90%，未覆盖登记 FU-xxx）并逐条标注理由，禁止静默裁剪（§2.16.6 第 3 条）；`begin` 校验 SC- 编号；L0 纯文档变更可单条 SC 标"无业务场景影响"——禁止留空。

## 2.5 阶段 5·注释与编码细则

- **中文注释规格（强制）**：① 类/接口：`@author` + 职责一句话；② 方法：公共 API/复杂逻辑/契约变化说明职责、`@param`/`@return`/`@throws` 与业务约束（简单私有方法不强制 Javadoc），改动处最小范围标 `CHG-xxx`；③ 关键逻辑 **WHY 注释**：解释"为什么"（业务原因/边界取舍/防坑），非 WHAT；④ 契约字段：DTO/VO 新字段注释含义与可空性；⑤ 降级/兜底路径：异常分支注明触发条件与降级行为。
- **ReAct 微循环（v2.21.0，每次源码修改强制）**：每次改动前后按三段式走（铁律句在 DS §2.16.2；细则唯一承载=本册 §2.16.2）；**禁止"上来就改代码"**（§5 严重违规）。

## 2.5 阶段 6·根因方法细则

- **根因分类（互斥单选，v3.10.0）**：需求缺陷 / 设计缺陷 / 实现缺陷 / 集成环境故障 / 数据缺陷 / 流程缺陷（检查缺口/文档漂移）；判定用各类**消歧问题**（含否定判别）并**引用证据行**（无证据时分类塌缩到泛化类，arXiv:2602.02475 Table 5）；无法归类须给自定义类名（禁空）；可扩展。
- **最早未恢复失败点（v3.10.0 三步扫描）**：定位首失败 → 查是否已被既有防线恢复 → 未恢复即根因点；**晚期显著症状可能只是下游表现**，分类须在最早未恢复点做（arXiv:2602.02475 §2.1/§4.7）。
- **BUG 与 CHG 不双建（v3.26.0）**：缺陷处置默认**只**落 `docs/bugs/<BUG-xxx>/` 六件套 + `bugfix-log.md` 双登记，**禁止为同一缺陷同时新建 CHG/变更目录**（两套承载同一事实 = 漂移温床）。仅当满足升级条件之一才开变更轨：①修复引入需求/功能行为变化（需 REQ/RTVM 链）；②跨系统契约/结构变更；③L2/L3 修复需独立签署。升级时变更目录号用 `BUG-xxx`（L0/L1 可入 BATCH，§1.1），`00-governance.json` 的 `bug_ref` 指向六件套；**诊断/根因正文以六件套为唯一权威，变更目录只引用不复制**。
- **六件套执法闭环（v3.34.0）**：`bug_ref` 支持扁平字符串**或字符串数组**（声明但不可解析即 die，fail-closed——数组曾被 `json_field` 静默跳过校验）；gate staged/stop/CI 逐组扫描 `<bugs_root>/BUG-*/` 六件齐（豁免 = `<bugs_root>/.gate-allowlist` 登记理由）；审计 **G8** 接管六件套存在性、**A21** 校验其盖章；六件套交付前跑 `scripts/stamp-provenance.sh --bug <BUG-id>`。

## 2.16.2·ReAct 三段式细则

> 铁律句与落点 A 层语义在 DS §2.16.2；本节承载四行细则：

- **Thought（先分析）**：陈述当前状态、目标与**全局影响判断**——引用阶段 2 三维分析与 §2.16.1 调研结论，明确波及的调用方/流程/业务；**不得只看待改文件**。
- **Action（后执行）**：按 Thought 结论执行；范围不得超出已分析影响面，发现新影响点先回 Thought 补分析。
- **Observation（必验证）**：执行验证命令（测试/`grep -c`/`wc -l`/`git diff` 等），归档**过滤后关键输出**（建议 ≤10 行）与完整日志落点文件，**禁止把整段原始输出贴入对话或产物**（v3.23.0）；不符禁止推进，回 Thought 重析。
- **落点（A 层可验）**：各阶段 Thought 摘要与 Observation 记录归档 09 CHG「执行记录（ReAct）」字段（§4，随 CHG 不可变）；缺失由 stop/CI 拦截（A 层），逐阶段完整性由 Review Agent 门禁 5 核对（B 层，§5）。

## 2.16.6·防漏红线细则

> 七条红线条目名与优先级声明在 DS §2.16.6；本节承载逐条完整细则（约束 AI 最常见失效模式——长任务中悄悄省略、用摘要代替核对、"大体完成"时提前标记）：

1. **逐项引用核对（v3.23.0 起，替代旧"逐条抄录"）**：声称任一阶段/门禁/DoD 完成前，必须把对应清单（§2.16.3/§2.16.4/所属阶段 §2.5 必含清单）**逐项列出条目号并勾选** `[x]`/`[ ]`，每项附一句结论——A 层项附校验命令与**过滤后关键输出行**（勿贴全文），B 层项附独立角色签署；**不要求抄录清单原文**（条目号引用即可，原文只在规范一处留一份，上下文与产物双份 verbatim 复制是反模式），禁止总结句代替，无逐项清单佐证的完成声明无效。
2. **缺失即未完成**：任一项无对应产物/证据即该环节未完成，不得整体标记"完成"，必须继续执行或明确报告"未完成 + 阻塞原因 + 所需输入"；**不允许大部分已完成就整体标完成。**
3. **禁止静默降级/跳过**：不得以"看起来不重要"自行跳过；跳过必须写明编号与理由，并区分"未命中，不适用"（§2.5）与真跳过。
4. **禁止"部分执行当全部执行"**：例如全量回归只跑了受影响模块，不得在清单勾选"全量回归通过"，必须如实标注"部分回归"并按 §2.13.4 走"未完成/有条件通过"流程。
5. **预算不足显式声明**：预估步骤/token 不足以完成全部 10 阶段 + 5 门禁时，须不晚于阶段 3 向编排者/人类声明"建议分批，已完成到 ___ 阶段"，禁止结尾才发现遗漏或压缩执行深度（如把跑测试简化为"预期会通过"）。
6. **完成声明的最终格式**：AI 在一次变更的最终交付消息中，必须包含以下三部分，缺一不可：① 本次风险等级判定（§0.5）及理由；② §2.16.3 DoD 全部条目逐条 `[x]`/`[ ]` 结果（不可用"以上均已完成"代替逐条罗列）；③ 如有任何 `[ ]` 未完成项，列出后续处理人与预计完成方式。
7. **复核义务**：编排者/人类采信子 Agent"已完成"结论前，必须按第 1 条抽查清单对应产物是否真实存在（如 05 是否真有本批次控制台输出），不得仅采信汇报；不符按 §5"口头宣称测试已通过"同级处理。
