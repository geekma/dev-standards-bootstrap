# 项目级总册与评审记录（Project Master Set，v3.36.0）

> **定位**：本文件是规范 §1.3「项目级总册」的**唯一权威细节层**——12 册的清单、必含章节、
> 独立完整原则、回填与变更注记语义、评审记录形状，全部以本文件为准；规范正文只保留
> 定义与执法锚点，禁止在别处重复展开。目标仓库落点 `docs/project/`（路径根可配置，
> §1.1；`--core` 随 `resources/templates/project/` 下发骨架）。
>
> **为什么需要总册**：变更轨（`docs/changes/`）与功能轨（`docs/<feature>/`）回答
> "某次变更/某功能改了什么"；总册回答"**项目现在整体是什么**"。没有总册，任何一次
> 变更（哪怕 L0）都无法回答"总需求/总架构/接口全景是否被这次变更波及"——总体与
> 部分的关联断链。总册是**聚合活文档**：每次变更回填对应章节并留变更注记，原值可查。

## 1. 独立完整原则（每册自足，禁止"仅见他册"）

1. **自含正文**：每册必含章节的**正文写在本册内**；跨册信息允许"引用链接**补充**"，禁止把本册该有的内容**唯一**寄存在另一册（评审、审计、AI 上下文构造都按单册进行）。
2. **头部自证**：每册第一屏必须能让读者回答"这是什么册、覆盖什么范围、是否独立完整"——以「总册编号：Pxx」行 + 「独立完整声明」行（逐字含 `独立完整声明`）承载。
3. **单册可评审**：评审记录按单册组织；评审人不必读齐 12 册即可签署对应册。
4. **索引不复制矩阵**：对 01.5/05/06.5 等唯一权威文件，总册只放**短引用行**（同 §4 追踪矩阵映射的"短引用 ≠ 复制"纪律）——两处维护必漂移。

## 2. 回填与变更注记语义（每次变更强制，整体-部分关联 + 有据可查）

- **回填清单（每次变更必填）**：`09-changelog.md` 每个 CHG 条目新增「项目总册回填清单」节——12 册**逐册一行**，形状 `- [x] P01 已回填（章节：需求全景索引；变更注记 CHG-xxx）` 或 `- [ ] P01 未命中（理由：纯配置变更，未触及需求）`。禁止删行、禁止留空、禁止整节标"全部未命中"而不逐册给理由（§2.16.6 第 3 条）。gate stop/CI 逐册机校（P00–P11 逐行出现且带 `[x]`/`未命中`）。
- **变更注记（册内留痕）**：被更新的章节末尾追加一行 `> 变更注记 CHG-xxx（YYYY-MM-DD）：<一句变动摘要>`——任何人打开总册任意章节，都能看到"这节最后被哪次变更、为何而改"。
- **原值可查**：总册是活文档（回填可覆盖旧正文），**历史原文由变更目录快照 + 09 CHG「方案」节承担**（§2.15 规则 2：任何正文覆盖必须能在 changelog 追溯，否则按覆盖丢历史拦截）；变更注记行本身**追加不删**（换行追加新注记，旧行保留）。
- **回填触发面**：需求/功能行为变化 → P01；流程/顺序/时序变化 → P02；接口/契约变化 → P03（联动 §2.13.3）；表结构/配置/DB → P04；任务/里程碑 → P05；测试策略/TC 增删 → P06；测试结论/覆盖率 → P07；部署/环境/配置基线 → P08；风险/FU → P09；**每次变更（无条件）** → P10（CHG 总索引追加一行）；决策变化 → P11。**判不准就多回填**——漏回填由 Review（门禁 5 B 层）与审计 G9 拦截。
- **Bug 处置特别条款**（§2.5 阶段 6，v3.35.0）：①**诊断前必读总册**——读 P01/P02/P03/P04 中与该缺陷相关章节并在 `01-diagnosis.md` 引用已读章节（防"只见代码不见设计"，设计遗漏类根因必须对照 P02 判定）；②**TC 覆盖强制**——修复落点必须被 TC 直接覆盖：既有 TC 可覆盖则复跑留证据；**不可覆盖必须新增防回归 TC**（04 新增 TC 行 + `03-test-plan.md` 对应），禁止"修复无 TC"或"仅复跑不新增"糊弄；③回填清单照常逐册勾选（缺陷大多命中 P02/P04/P07/P09/P10）。

## 3. 初始化（首次变更强制）

- 仓库**第一次变更**（`docs/project/` 尚无 12 册）时：先复制骨架 `resources/templates/project/`（安装后位于 `<docs>/templates/project/`）到 `docs/project/`，**回填现状合成实文**（从 README/既有 01-spec/代码现状提炼；冊内容可以薄，但必含章节不可缺），并逐册完成初评（`reviews/` 12 份）——**然后才允许 `agent-gate begin`**（begin 机校 12 册存在；豁免须 `AGENT_GUARD_ALLOW_NO_PROJECT_MASTERS=1` 且在 09「重要上下文」登记理由，fail-closed 不是静默旁路）。
- 存量仓库升级到 v3.35.0 后：**下一个变更**的 begin 同样强制（存量回填义务见 STANDARDS_CHANGELOG 对应行，§2.14）。
- 源仓自身已随 v3.35.0 实例化 `docs/project/`（dogfood 基准形态）。

## 4. 评审记录必含章节（每份 R 册，机器可验锚点）

```markdown
# <册名> 评审记录（R-Pxx）

> 总册编号：Pxx ｜ 评审对象：docs/project/<册文件名> ｜ 更新语义：追加式（新节置顶，旧结论保留）

## 评审 YYYY-MM-DD（CHG-xxx / 初始化）
- 评审人（角色 + §2.1.7 署名：platform / model / task）：
- 逐章结论（必含章节逐项：通过 / 问题）：
- 发现问题与整改闭环（问题 / 落点 / 状态）：
- 独立性声明（评审人 ≠ 册作者）：
```

- **独立性**：册主要作者与评审记录签署人不得为同一主体（L0/L1 最低线=评审独立，§2.1 规则 10）；初始化初评同理。
- **时机**：初始化初评 + 每次对该册的**实文回填**后追加评审节（纯注记行追加可不重评，由 Review 在 CHG 内核）。

## 5. 机器校验契约（gate 与审计各自查什么，防止两处口径分叉）

| 检查 | 执行者 | 内容 |
|---|---|---|
| begin：12 册存在性 | `agent-gate begin` | `docs/project/` 下 P00–P11 十二文件存在且非空（骨架含 TEMPLATE-MARKER 亦放行——填充义务由 stop/Review 承担）；缺失即 die（豁免见 §3） |
| stop/CI：回填清单 | `agent-gate stop` / branch CI | 09 活跃变更条目含「项目总册回填清单」节，P00–P11 逐行出现且同行带 `[x]` 或 `未命中` |
| 审计 G9：总册存在与自证 | `tests/audit-docs-consistency.sh` | 12 册存在、逐册含 `总册编号：Pxx` 与 `独立完整声明`、`reviews/` 12 份成对存在；最新变更 09 含回填清单节（存量回填清单语义，§2.14） |
| 审计 G8/A21：缺陷组双形态 | 同上 | 六件套扫描覆盖 `<bugs_root>/BUG-*/` 与 `<bugs_root>/BATCH-*/BUG-*/` 两种布局 |
| 内容质量 | B 层 Review（门禁 5） | 必含章节实文非占位、回填与实动一致、变更注记可追溯 |

> 模板骨架**不得预置**回填清单的可勾选结论或"独立完整声明"以外的结论性文字——与 `03.5` 骨架同纪律：空骨架必须填，不许绕过（§2.17.1）。
