# 数据结构设计规范（Data Structures Methodology）

> **定位**：本文件是数据建模决策（规范 §2.5 阶段 1 输入输出契约、阶段 3 数据设计、阶段 5 实现）的工程依据，M0 强制基线（见 `docs/METHODOLOGY.md` §3.3）。核心主张：**结构化类型是系统内一切信任的前提**——弱类型穿层（`Map<String,Object>` / `any` / 无 schema 的 dict）意味着编译器与 Reviewer 同时失明。
> **读取时机**：定义任何接口字段、LLM 输入输出、缓存载荷、消息体之前。

---

## 1. 六类模型分类（职责与归属）

| 模型 | 定义 | 唯一归属层 | 禁止事项 |
|---|---|---|---|
| **Entity** | 有身份与生命周期的领域对象（如 `Order`，靠 ID 判等） | 领域层 | 禁止直接序列化给外部；禁止携带展示逻辑 |
| **DTO** | 跨进程/跨层传输的数据载体，无业务规则 | 契约层（对外接口/服务边界） | 禁止内部逻辑直接消费；字段变更 = 契约变更，走 §2.13.3 生命周期 |
| **VO** | 无身份的值对象（如 `Money`、`Address`），不可变 | 领域层（值语义） | 禁止可变字段；判等按值不按引用 |
| **Command** | 写操作意图载体（含参数校验规则） | 应用层入口 | 禁止携带查询字段；禁止复用一个结构同时当读写入参 |
| **Query** | 读操作参数（含分页/过滤条件） | 应用层入口 | 禁止副作用字段（如查询结构里混入 update 标志） |
| **Event** | 已发生事实的不可变通知（含事件版本与时间戳） | 领域/集成层 | 禁止携带"期望未来发生的事"（那是 Command）；禁止消费方回写 |

**转换规则（M0）**：
1. Entity ↔ DTO 必须**显式映射**（独立 converter/assembler），禁止框架隐式穿透后在边界两侧引用同一类型。
2. Command → Entity 在应用层入口完成校验后转换；领域层不再重复校验入参。
3. Entity → Event 抽取时只能携带事实快照，禁止引用 Entity 本身（防事件消费方反向耦合领域内部）。
4. **为什么不用（防过度映射）**：单体内同一进程的内部两层之间、且字段完全一致无演化差异时，允许标注后直传（注释说明"与 X 层共用，变更须双侧评估"；对外契约边界不适用此豁免）——每层各建一套字段全同的 DTO 属于映射洁癖。

## 2. 五项属性规范

### 2.1 不可变性（默认不可变）

- 新建结构默认 `final` 字段 / `readonly`；集合字段返回不可变副本。
- 允许可变的两类场景（须注释论证）：① 构建期（builder / 累加器，构建完成后冻结）；② 已用 profiler 证明的热点路径。
- **为什么用**：不可变结构天然线程安全（联动 development.md §3.6），且能安全地跨层/跨线程/进缓存。
- **为什么不用（降级）**：高频原地更新的算法结构（聚合中间态）强行每次复制会造成 O(n) 浪费——这类须注释豁免。

### 2.2 可空性（显式声明）

- 每个字段可空性必须**在类型或注解上显式**（`Optional` / `@Nullable` / TS `?`），禁止"看实现猜可空"。
- 集合字段默认空集合而非 null（调用方零判空）。
- **LLM 输出字段全部视为可空，直至校验通过**——包括"模型显然总会返回"的字段（联动规范 §2.9.3 幻觉防护）。
- **为什么用**：可空性是接口契约的一部分，隐式 null 是 NPE/空指针类缺陷的第一来源。

### 2.3 校验（边界一次）

- 校验发生在**系统入口**（外部请求、LLM 输出解析、消息消费）转换处；内部代码信任已校验数据，不层层重复校验。
- LLM 输出必须先过 schema 校验（字段存在性/类型/枚举值域），校验失败进入降级结构（§4.3），禁止半校验结果继续流入业务。
- **为什么不用（防校验洁癖）**：内部私有函数对已校验入参再逐字段判空属于重复防御——用断言或文档标注前置条件即可。

### 2.4 序列化（契约显式）

- 对外契约字段必须**显式命名注解**（`@JsonProperty` / `@SerializedName` / TS 显式类型），禁止依赖语言默认命名规则（编译器重构字段名会静默破坏线上契约）。
- 命名风格在一个契约内统一（camelCase 或 snake_case 二选一），跨端以 schema 文件（OpenAPI/TS 定义）为准。
- 日志/埋点中的结构必须先脱敏再序列化（规范 §2.9.4）。

### 2.5 版本兼容（演进规则）

- 新增字段必须**可选**（默认值或可空），旧消费方忽略未知字段的能力须在 03 兼容性节确认。
- 删除/重命名字段走双写过渡期：先加新字段双写 → 消费方全部迁移 → 删旧字段（每步独立 CHG，联动 §2.13.3）。
- **为什么用**：契约破坏是静默的——发布方正常，消费方在字段消失的第一次调用才爆炸，爆炸半径见 02 影响分析。

## 3. 弱类型禁令（M0，严重违规）

**禁止 `Map<String,Object>` / `any` / `object` / 无 schema 的 dict 直接穿越层边界**（接口返回、服务间调用、消息体、缓存值）。

允许的例外**仅两类**，且必须注释标注作用域与理由：
1. **边界反序列化瞬态**：JSON → 结构的解析瞬间，须在**同一个函数内**转换为强类型后立即丢弃，禁止作为返回值传出。
2. **日志/埋点脱敏载荷**：只写不读的载荷结构（读它 = 违规）。

**为什么用**：弱类型把"字段名拼错、类型不符、结构漂移"全部从编译期推迟到运行期生产事故；对 LLM 链路更是双重放大——模型输出本身不确定，再叠加无类型消费，缺陷无法定位。

## 4. LLM 链路专项（叠加规范 §2.9）

1. **输入输出结构分离**（M0）：prompt 输入结构与输出结构不得共用类型——输入侧字段增删与输出侧 schema 版本化是两个独立演化节奏。
2. **输出 schema 版本化**：每次模型/提示词变更，输出 schema 必须可 diff（版本号 + 变更记录入 06.5 配置记录，联动 §2.9.2 prompt 门禁）。
3. **降级结构显式建模**：解析失败/空响应的兜底返回是**独立类型**（含失败原因枚举），禁止返回 null 或空 Map 让下游猜。
4. **流式输出**（如适用）：分片结构须含序号与完成标志，聚合器对乱序/截断有显式处理路径。

## 5. 反向检查（用真实结构过一遍）

**场景：LLM 建议类接口的返回结构（通用建议/分析类系统）。**

**反例**（按本文件应判退回）：

```java
// 违规：弱类型穿层 + 隐式可空 + 无降级结构
public Map<String, Object> analyze(String sessionId) {
    String raw = llmClient.call(promptOf(sessionId));
    return JSON.parseObject(raw);  // Map 直接透传给前端
}
```

问题清单：`Map<String,Object>` 跨层（§3 严重违规）；字段可空性未知（§2.2）；解析失败无降级（§4.3）；前端消费处每取一个字段都是隐患。

**正例**：

```java
/** LLM 分析结果契约（CHG-xxx）：字段可空性显式，schema 版本化 */
public record AnalysisDTO(
    @JsonProperty("summary") String summary,            // 可空：模型可能省略
    @JsonProperty("confidence") Double confidence,        // 可空：降级时无置信度
    @JsonProperty("schema_version") String schemaVersion // 必填：输出 schema 版本
) {}

/** 解析失败降级结构：显式建模，禁止 null 透传 */
public record AnalysisFallback(FallbackReason reason, String rawExcerpt) {}

public Either<AnalysisFallback, AnalysisDTO> analyze(String sessionId) {
    String raw = llmClient.call(promptOf(sessionId));
    return AnalysisSchema.parse(raw)          // 边界 schema 校验（§2.3）
        .map(Either::<AnalysisFallback, AnalysisDTO>right)
        .orElseGet(() -> Either.left(new AnalysisFallback(PARSE_FAILED, excerpt(raw))));
}
```

**Review 操作**：挑本次变更的 1–2 个真实结构（对外契约、LLM 输入输出优先）逐字段过 §1–§3；发现弱类型穿层按 `docs/METHODOLOGY.md` §2 统一分级记入 07-review-report.md（M0 违反=严重）。
