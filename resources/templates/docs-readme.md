# 文档地图（docs/ README）

> 本文件由 dev-standards-bootstrap 生成并随升级刷新——**只指路，不定义**；规则细节一律以 `AGENTS.md`（入口）与 `DEVELOPMENT_STANDARDS.md`（权威全文）为准，勿在此另立规范。

## 五层职责与更新时机

| 层 | 落点 | 角色 | 何时更新 |
|---|---|---|---|
| 功能轨 | `docs/<feature>/` | 需求/设计正文唯一权威：`01-spec.md`（REQ 全文/DoD/验收）、`01.5-rtvm-matrix.md`（REQ→DES→TASK→TC 四维链路） | 随变更回填；需求变更只改 01-spec |
| 变更轨 | `docs/changes/<变更号>/` | 一次变更一组文档（00-intent…09-changelog），门禁机校落点 | 每次变更新开一组，已闭合禁改写 |
| 项目总册 | `docs/project/` | **索引与聚合层**（P00–P11 十二册）：只放指针/统计/短引用，不复制正文与矩阵 | 每次变更逐册回填 + 变更注记（09 回填清单机校） |
| 缺陷组 | `docs/bugs/` | 缺陷六件套（诊断/影响/测试计划/矩阵/配置/任务），同日入批 `BATCH-YYYYMMDD/` | 每次缺陷处置新起锚点小节 |
| 治理件 | `AGENTS.md`、`templates/`、`methodologies/`、`STANDARDS_CHANGELOG.md`、审计/门禁脚本 | 框架自身，门禁按路径机校 | 仅随 `--upgrade` 刷新，勿手改 |

## 三条硬规则（防文件散乱）

1. **评审记录唯一落点（§1.3 第 6 条）**：变更轨 `07-review-report.md`（变更/缺陷评审）+ `docs/project/reviews/`（逐册配对）；**功能目录不建 `reviews/` 等落点表外子目录**，功能级评审结论并入该功能 `01-spec.md` 评审节或变更轨 07。
2. **总册不复制正文**：P01 需求全景索引等只放统计行 + 指针表；REQ/DES/TC 全文唯一权威在功能轨/变更轨原文件（"哪个 01 最新"→ 总册 Pxx-*.md 永远只是索引，`01-spec.md` 才是正文）。
3. **表外文件默认禁止**：任何新文档先查规范 §2.16.5 落点表，表外不建；确需新落点先走变更修订规范，不在仓里即兴散落。
