# BUG-xxx 影响关联矩阵（缺陷文档组 · 之二）

> **定位**：缺陷文档组三件套之二（规范 §2.5 阶段 6，v3.6.0）——逐项盘点本次缺陷影响的需求 / 设计 / 变更 / 文档 / 遗留项并给出处置落点，与 `01-diagnosis.md`、`03-test-plan.md` 互链。
> **只读纪律**：本目录闭合后**只增不改**；衍生影响**新起一组**缺陷文档目录并经「关联缺陷」引用本组。

## 影响关联矩阵

| 关联对象 | 编号 | 影响判断 | 处置（含落点） |
|---|---|---|---|
| 需求 | `REQ-xxx` / 无 | 受影响（行为偏离规格）/ 不受影响（理由） | 01-spec 需求影响节回填 / 01.5-rtvm 验收标准回补 / 无需处置（写理由） |
| 设计 | `DES-xxx` / 无 | 根因为设计遗漏？ | 根因为设计遗漏时**必须回补 DES**（落点） |
| 变更 | `CHG-xxx` | 本次修复所在变更 | 关联 CHG 条目「Bug 修复回填清单」逐项勾选 |
| 文档 | README / 方案 / 配置等 | 描述与实际行为不一致 | 逐项回填（写明落点文件与节） |
| 遗留项 | `FU-xxx` | 修复引入或顺带发现 | 登记 FU 并链接（来源与理由） |

（五类逐项必须有结论；「不受影响」也是有效结论，需给理由，禁止留空。）

## 关联缺陷（横向引用）

- 旧组：`BUG-xxx`（同族 / 衍生，`docs/bugs/BUG-xxx/`）——只引用，不回改
- 新组（衍生缺陷）：另起 `docs/bugs/<新BUG-xxx>/` 三件套并在元信息「关联缺陷」回指本组

## 验收标准

- [ ] REQ / DES / CHG / 文档 / FU 五类逐项有结论
- [ ] 根因为设计遗漏时已回补 DES
- [ ] 与 bugfix-log 条目及关联 CHG「Bug 修复回填清单」逐项一致
